# 회의록 자동화 도구 — 명세서 (v0.6)

## 만들 것

회의 녹음 파일 하나를 넣으면, 사람 개입 없이 회의록 정리본이 노션에 올라가는 명령줄 Python 스크립트.
시간대·화자별 원문은 검수용으로 같은 페이지에 둔다. 서버, DB, 웹 화면은 만들지 않는다.

## 단계

| 단계 | 입력 → 출력 | 성격 |
|---|---|---|
| 1. 음성 인식 | 녹음 → 단어 목록(화자 번호, 시각) | 다글로 API (화자 분리 사용, 파일 직접 업로드) |
| 2. 원문 만들기 | 단어 목록 → `발언 번호 / 시각 / 화자 / 내용` | 일반 코드 |
| 3. 추출 | 원문 → 제목·요약·대화 주제·결정사항·할 일 JSON | Claude API 1회 호출 (모델 `claude-opus-5-5`, JSON 스키마로 응답 형식 강제) |
| 4. 근거 검증 | 추출 결과를 원문과 대조 → 정리본 + 제외 목록 | 일반 코드 |
| 5. 노션 기록 | 정리본·제외 목록·원문 → 회의록 DB의 페이지 1개 | 노션 API. 회의일은 녹음 파일 수정 시각(틀리면 노션에서 직접 고친다). 레코드 제목은 회의일, 같은 날 여러 번이면 뒤에 (1), (2). 회의 ID는 속성. 본문에 정리본·제외 목록, 맨 아래 하위 페이지에 원문 표 |

- LLM은 3단계에만 쓴다. 단계 순서는 코드가 정한다.
- 단계끼리는 `runs/<회의ID>/` 안의 파일로 이어진다. 회의 ID는 녹음 파일의 해시다. 실패한 단계부터 다시 실행할 수 있어야 한다.
- 외부 서비스 호출은 서비스마다 파일 하나로 분리한다. 그 이상 복잡한 구조는 만들지 않는다.
- 녹음은 다글로 비동기 STT API에 multipart/form-data로 직접 올린다(API Reference에서 확인, 최대 2GB·4시간). S3 등 중간 저장소와 URL 방식은 쓰지 않는다.

## 꼭 지킬 것

- LLM이 지어낸 항목을 걸러낸다. 3단계에서 결정사항이나 할 일을 뽑을 때, 근거가 된 발언의 번호(2단계에서 붙인 번호)를 함께 적게 한다. 4단계에서 코드가 그 번호가 원문에 실제로 있는지 확인한다. 없으면 정리본에서 빼고, 뺀 항목은 제외 목록에 따로 남긴다. 정리본에는 근거를 그 발언의 시각으로 표시한다.
- 화자는 번호(화자1, 화자2…) 그대로 쓴다. 누구인지 추정하지 않는다.
- 노션에는 승인 없이 바로 기록한다. 상태는 "자동 생성(미검수)". 본문 순서는 정리본 → 제외 목록 → 원문.
- 같은 회의로 다시 실행해도 페이지를 중복으로 만들지 않는다. 지정한 DB 밖은 건드리지 않는다. 앞 단계가 실패하면 페이지를 만들지 않는다.
- 실행마다 단계별 소요 시간, 추출 항목 수, 제외 항목 수를 로그로 남긴다.
- API 키는 환경 변수로만 읽는다. 키, 녹음, 원문, `runs/`는 저장소에 올리지 않는다.

## 완료 기준

- 실제 회의 녹음 파일 하나를 넣으면 사람 입력 없이 노션 페이지가 생긴다. 완료 판정은 이 결과로만 한다. 대역을 쓴 테스트 통과는 완료의 근거가 아니다.
- 2단계와 4단계는 고정 표본으로 자동 테스트한다: 화자가 바뀌면 발언이 끊긴다 / 빈 입력에서 죽지 않는다 / 가짜 근거 번호를 단 항목이 제외된다 / 정상 항목은 통과한다.
- 같은 녹음으로 두 번 실행해도 페이지가 하나다.
- 완료를 보고할 때 실행 결과와 하지 못한 것을 함께 낸다. 실행해 보지 않은 것을 "동작한다"고 보고하지 않는다.

## 용어

| 용어 | 뜻 | 산출물 | 이 프로젝트에서 |
|---|---|---|---|
| 테스트 | 자동으로 돌아가고 통과/실패로 떨어진다. 기대값을 코드에 박아 두고 매번 같은 답이 나와야 한다 | `OK` / `FAILED` | `tests/`, `py -3.12 -m unittest` |
| 실험 | 답을 모르는 질문을 놓고 조건을 바꿔 가며 측정·비교해 결론을 낸다 | 보고서 | `experiments/`, 실험마다 폴더 하나 |
| 실행 확인 | 실제 데이터로 한 번 돌려 실제로 되는지 본다. 테스트도 실험도 아니다 | 결과물(노션 페이지 등) | `run.py`를 실제 녹음으로 실행. 완료 기준이 이것 |

영어로는 test / experiment(evaluation, benchmark) / smoke test(manual verification)에 해당한다. 셋을 "테스트"로 뭉뚱그려 부르지 않는다.

## 미정 (계획을 세우기 전에 질문할 것)
