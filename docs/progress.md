# 진행 상황 (2026-10-06 갱신, 일곱 번째)

## 목표

회의 녹음 파일 하나를 넣으면 사람 개입 없이 회의록 정리본이 노션에 올라가는 명령줄 Python 스크립트 (`docs/spec.md`, v0.6).
**5단계 전부 완성, 명세서 완료 기준 충족.** 지금은 다음 개선인 **교정 단계**(STT 오인식 교정)를 실험 중이고, 함께 **비용 절감**(Opus → Sonnet)을 검토 중이다.
`docs/spec.md`는 사용자가 브레인스토밍한 것을 AI가 받아 적은 문서라 계속 바뀔 수 있다.

작업 방식: 사용자는 각 스크립트를 코드 레벨이 아니라 흐름(flow) 중심으로 이해하고 넘어가길 원한다. 새 스크립트를 만들면 함수별 역할을 설명하는 시간을 가진 뒤 다음 단계로 간다. 혼자 하는 프로젝트라 PR은 쓰지 않는다. 실험은 사용자 요청으로 브랜치(`experiment/correction`)에서 한다. 커밋·push는 사용자가 시킬 때 한다. 문서에는 사용자가 적으라고 한 내용만 넣고, 제안은 채팅으로 한다. 폴더 구조는 루트 `README.md`의 트리를 참고. 설계는 채팅으로 제안해 사용자 확인을 받은 뒤 구현한다.

**용어 (`docs/spec.md` "용어" 절)**: 테스트 = 자동 실행·통과/실패(`tests/`). 실험 = 조건을 바꿔 측정·비교·결론, 보고서(`experiments/`). 실행 확인 = 실제 데이터로 한 번 돌려 되는지 봄(`run.py` 실제 녹음). 셋을 "테스트"로 뭉뚱그리지 않는다.

## 진행 중

**교정 단계 실험** — 브랜치 `experiment/correction`, 파일 `experiments/correction/correct.py` (**커밋 안 함, untracked**). 파이프라인 본체(`llm.py` 등)는 건드리지 않았다. `report.md`와 `experiments/README.md` 목록 추가는 아직 안 함.

스크립트: `python experiments/correction/correct.py <회의ID> <none|plain|mark> [--context "..."] [--glossary 파일] [--out 폴더명] [--model claude-opus-5-5|claude-sonnet-5-5]`. `runs/<회의ID>/utterances.json`을 읽어 교정(발언 번호·내용만 보냄, 80개씩, 번호 집합 검사) → 같은 파일 안의 추출 코드(루트 `llm.py` 복사본, `prompts/extract.md` 사용)로 추출. 결과는 `runs/_experiments/correction/<회의ID>/<폴더명>/`에 `corrections.md`(바뀐 발언 전후), `extraction_review.md` 등. `none`=교정 없이 추출만(대조군), `plain`=spec 규칙대로 교정, `mark`=교정 + 고칠 확신 없는 말은 `[불명확: 원래 표기]` 표시, 추출 프롬프트에 "표시된 말로 주제·결정·할 일 만들지 않음" 추가. `--glossary`는 만들어 두었으나 아직 한 번도 안 씀.

계기: 2분 회의에서 "짧게 일하는"이 "짜갱이"로 오인식 → 대화 주제에 "'짜갱이'에 주목한 이유 설명 추가 필요성"이 올라감.

2분 회의(`2bfc0703de20ad5a`) 결과, 각 설정 1회씩 실행:

| 폴더 | 모델 | 교정 결과 | 첫 대화 주제 | 비용 |
|---|---|---|---|---|
| `none` | Opus | - | 주제 선정 배경 보완('짜갱이'에 주목한 이유) | $0.046 |
| `plain` | Opus | 기업→기획 발표만 고침, 짜갱이 그대로 | '짜갱이'에 주목한 이유 설명 추가 | $0.085 |
| `mark` | Opus | 기업→기획, `[불명확: 짜갱이]`, `교수님 [불명확: 상]` | 주제 선정 배경 보완 및 분량 축소 | $0.083 |
| `mark2` | Opus | mark와 같음(`[불명확: 교수님 상]`만 범위 다름) | 주제 선정 배경 설명 보완 | $0.090 |
| `sonnet_none` | Sonnet | - | 짜갱이(단기 일)에 주목한 이유 포함 여부 | $0.027 |
| `sonnet_mark` | Sonnet | 기업→기획, `[불명확: 짜갱이]` (교수님 상은 놓침) | 주제 선정 배경의 내용과 분량 조정 | $0.040 |

- `mark`와 `mark2`의 차이는 불명확 규칙 문구뿐: `mark`는 "뜻이 통하지 않는데 고칠 확신도 없는 말", `mark2`부터(현재 코드)는 "존재하지 않는 말이거나 맥락에 어울리지 않는 말인데 고칠 확신이 없으면". 결과 차이 거의 없음. `mark` 실행 당시 프롬프트는 결과 파일에 저장 안 됨(이후 `correction_response.json`에 `system` 저장하도록 바꿈).
- 관찰: 교정만(`plain`)으로는 "짜갱이"가 안 걸러지고 불명확 표시(`mark`)가 있어야 엉뚱한 주제가 빠짐. "풀타임 공부"(아마 "풀타임 근무")는 어느 설정도 못 고침 — 문장 자체가 말이 돼서 맥락 없이는 어려워 보임. Opus mark는 표시 안 한 "구인장"까지 주제에서 흐려짐(2회 연속), Sonnet mark는 "구인장/구인자"로 정확히 남김. Sonnet mark는 결정사항 0개("주제 선정 배경 축소"를 할 일로 분류). **Sonnet none은 요약에 "짧은 단기 일(짜갱이)"라고 뜻을 추측해 씀**(Opus none은 "음성 인식 표기 그대로"라고 밝힘) → Sonnet을 쓰면 교정·불명확 표시가 더 필요.
- 한계: 2분 회의, 각 1회, 정답 원고가 이 컴퓨터에 없어 CER 못 잼. 할 일 개수가 같은 Opus에서도 3/2/3으로 바뀜(실행 변동).
- 사용자가 회의 맥락·단어 사전 방식을 제안함 → spec 설계와 같음. AI가 원문을 보고 초안(맥락 "단기 일자리 구인·구직 서비스 팀 프로젝트의 기획 발표 자료 검토 회의", 사전 "기획 발표, 주제 선정 배경, 구인자, 구직자, 페르소나, 공신력, 단기 일자리")을 냈으나 사용자 확인 전이고, 사용자가 "일단 그대로 두자"고 해서 보류. 공정한 비교를 위해 맥락·사전은 녹음을 보기 전 사람이 쓸 법한 수준이어야 한다(정답 단어를 넣으면 안 됨).

## 결정과 이유

- **교정 실험은 브랜치 `experiment/correction`, `experiments/correction/`에 자체 완결 스크립트로**: 사용자 요청. 파이프라인 본체를 건드리지 않고 비교만 하려고.
- **불명확 표시는 지우지 않고 감싼다**(`[불명확: 원래 표기]`): 사용자가 "말이 안 되는 단어는 쳐내거나 고치자"고 제안 → 지우면 "한 말을 없애는" 위험, 추측해 고치면 "안 한 말로 고치는" 위험이 있어 표시 방식을 제안했고 실험에 넣음. 확정은 아님.
- **모델 변경은 1시간 회의로 확인한 뒤**: 2분 회의 1회씩으로는 근거 부족. 사용자 방향은 "큰 차이 없으면 Sonnet 5.5".
- **교정 단계는 별도 단계로, STT 원본은 보존**: 사용자 결정("노션 원문을 사람이 읽으니 교정본이 필요하고 요약도 그걸로"). 원본 보존과 `corrections.md`로 위험 보완.
- **다글로 부가 옵션(키워드 부스팅, 화자 수 힌트)은 쓰지 않는다**: 실험 결과 효과 없거나 악화.
- **의미 없다고 결론 난 기능 코드는 커밋하지 않는다**: 사용자 지적.
- **실험은 `experiments/<실험명>/` 하나에 스크립트+보고서, 스크립트는 자체 완결**. 결과 파일은 `runs/_experiments/<실험명>/`.
- **파이프라인 LLM은 현재 Claude `claude-opus-5-5`, `effort="high"`**(5.5 기본은 medium). 단가 Opus 5.5 $4/$20, Sonnet 5.5 $2/$10, Haiku 4.5 $1/$5 (100만 토큰당 입력/출력).
- **요약은 원문 대체용 서술**(`275d2b8`), **"안건"이 아니라 "대화 주제"(`topics`)**. **4단계는 근거 일부만 가짜여도 항목 전체 제외**. **5단계 회의일 = 녹음 수정 시각**(파일을 옮기면 오늘 날짜, 사용자 결정: 노션에서 직접 고침).
- **노션은 `requests`로 REST 직접 호출**, API `2025-09-03`. rich_text 2,000자·블록 100개·표 99행 분할.
- 터미널 출력에 cp949 밖 문자(`≈`, `—`) 안 씀. 테스트는 함수 하나가 규칙 하나. 회의 ID = sha256 앞 16자. **API 키는 사용자가 `setx`, 에이전트는 값을 출력하지 않고 채팅으로 받지도 않는다.** `setx` 전에 켠 앱에서는 명령 앞에 `Set-Item "env:이름" ([Environment]::GetEnvironmentVariable(이름,'User'))`로 읽어 와 실행.

## 시도했다가 실패한 것

- **교정 `plain`(규칙만)** — "짜갱이"처럼 고칠 말을 모르는 오류는 그대로 둬서 엉뚱한 주제가 남음 → `mark` 추가.
- **불명확 규칙 문구 보강(`mark2`)** — "존재하지 않거나 맥락에 어울리지 않는 말"을 명시해도 결과가 `mark`와 거의 같음. "풀타임 공부"는 여전히 못 잡음.
- **키워드 부스팅**, **`speakerCountHint`** — 효과 없음/악화.
- 이 컴퓨터에서 `py -3.12` — `py` 명령 없음. `python` 사용.
- Bash heredoc 안의 `\\n`이 실제 줄바꿈으로 들어가 SyntaxError. 파이썬 문자열에 `\n`이 있는 코드는 Write/Edit 도구로.
- Bash 콘솔은 cp949라 한글 출력이 깨짐 — `PYTHONUTF8=1` 또는 PowerShell `Get-Content -Encoding utf8`.
- 요약 "3~5문장" 제한 — 50분 회의도 5문장. 제거.
